HARDWARE FINDING AND CONCLUSION

The user's MKII runs 2 DSP + 1 CF + 5 stock FLEX/STATIC tracks successfully,
but 2 DSP + 2 CF + 3 stock tracks becomes sluggish and locks. Algorithms in
this additional observation were unspecified. This prioritizes the second
CF voice; it does not prove Resonant, STATIC or cache contention as the cause.
Supplied PKH4O2 captures include 288.1 us average / 504 us max / 723 misses,
and a same-boot 9901-frame delta averaging 331 us with 20 additional misses.
The hardware JSON labels these supplied summaries; these new raw captures
were not independently decoded here. Deadline: 362.812 us; 80%: 290.249 us.

The selected implementation reduces text, executed code footprint and stack
requests while preserving two unrestricted CF voices. Wavetable dense-call
cycles regress slightly. Further compact-control alternatives reduce footprint
but increase CPU/stack work. Physical cache behavior could change the ranking.
The model passes even the known-failing PKH4O2 60-second STATIC workload.
It cannot establish hardware stability or a reliable unrestricted voice limit.

PRACTICAL PLATEAU / ARCHITECTURE

The ledger covers compiler O2/Os, selective inlining/outlining, hot/cold
smoothing, loop splitting/unrolling, alignment, EMAC, live-state, redundant
clear/copy, split callbacks, transport and diagnostic alternatives.
Four additional control-scope alternatives preserve exactness but lose the
selected balance. Compact controls reduce Snare/Bass executed union
19388/1322 -> 15340/1043, while adding ~483 cycles and ~1145 stack bytes per
dense two-voice frame. This is a real footprint/CPU frontier; it is not a
qualified installation image. All patches/receipts are preserved.
Blind cache coloring/relocation lacks a calibrated silicon latency oracle;
sharing independent RNG/control work or changing stock transport violates
preserved semantics/ownership. These blockers are not a proof of optimality.
Physical results can reopen the compact-control frontier.

Preferred maximum remains 2 DSP + 2 unrestricted CF. No necessary restriction
can be inferred from all-pass local results. If hardware still rejects it,
first reopen the compact-control/cache frontier with a separately qualified
unrestricted A/B candidate; the model cannot rank that silicon tradeoff.
Only if unrestricted optimization remains insufficient should alternatives
be evaluated: empirically successful lower-cost pairs, then one unrestricted
plus one limited CF, then one CF only. WT's second voice saves ~5.01 us relative
to Snare's mean modeled IRQ increment; removing Snare's second saves ~24.80 us
in this fixture. Neither establishes sufficient silicon margin. The user
must approve restrictions; none is implemented. Reported one-CF success does
not establish every algorithm/control workload as hardware-qualified.

The hardware procedure prioritizes Snare/Snare, Snare/Bass and Bass/Bass,
then WT controls, all 25 ordered choices and increasing STATIC activity.
STOP cannot export after a total lock; bounded same-boot snapshots preserve
pre-failure deltas without filesystem writes in the audio path. Only MKII
measurements can accept hardware stability or diagnose physical contention.
